1. mutex(queueMutex)의 역할

Mutual Exclusion(상호 배제). 여러 스레드가 하나의 자원(여기서는 frameQueue)에 동시에 접근해서 메모리가 깨지는 것을 막아주는 열쇠(자물쇠) 역할.

ㅇ 필요한 이유: captureThread는 큐에 프레임을 넣으려고 하고(push), mainThread는 큐에서 프레임을 빼내려고(pop) 합니다. 만약 두 스레드가 정확히 같은 찰나의 순간에 큐를 건드리면 에러가 발생합니다.

ㅇ 작동방식: 한 스레드가 열쇠(mutex)를 쥐고 큐를 작업하는 동안, 다른 스레드는 열쇠가 반납될 때까지 대기합니다.


2. frameDelayMs를 구할 때 1000을 FPS로 나누는 이유?
1초는 1000ms입니다.
ㅇ FPS는 1초 동안 보여줄 프레임의 개수를 의미합니다.
ㅇ 따라서 프레임 1개가 화면에 머물러야 하는 시간(ms)을 구하려면 전체 시간(1000ms)을 프레임 개수로 나눠야 합니다.
ㅇ 예시: 30FPS 영상이라면 1000 / 30 = 33.33ms. 약 33.33ms마다 프레임을 하나씩 넘겨야 원본 속도가 됩니다.


3. 중괄호{}로 묶은 이유? 그리고 std::lock_guard의 의미
C++의 RAII(Resource Acquisition Is Initialization) 특성을 활용해 잠금의 범위를 최소화.
C++에서는 변수가 자신이 속한 중괄호를 벗어나는 순간 메모리에서 즉시 소멸합니다.

std::lock_guard<std::mutex> lock(queueMutex);의 의미
ㅇ 생성될 때: queueMutex 열쇠를 잠급니다.
ㅇ 중괄호를 나갈 때: lock 변수가 소멸하면서 queueMutex 열쇠를 자동으로 반납합니다.


4. elapsed 계산시 count()를 쓰는 이유
ㅇ duration이라는 시간 객체 상태에서는 바로 숫자 연산을 하기 어렵습니다. 그래서 객체 내부에서 순수한 정수 숫자값(예: 5)만 밖으로 추출해 내는 함수입니다.


5. sleepTime 원리
   
목표는 프레임 간 간격을 정확히 frameDelayMs(예: 33ms)로 맞추는 것입니다.
ㅇ 하지만 프레임을 디코딩하고(cap >> frame) 큐에 넣는 과정에서 이미 elapsed(5ms)만큼 소모되었습니다.
ㅇ 만약 소모된 시간을 무시하고 33ms를 쉬어버리면 전체 주기는 38ms가 되어 영상이 점점 느려집니다.
ㅇ 따라서 목표주기(33ms)에서 이미 일하느라 쓴 5ms를 뺀 나머지 시간(28ms)만 재워야(sleep) 전체 간격이 정확히 33ms가 됩니다.

1. condition_variable은 뭘 하는 애야? 
notify_one 얘가.. 대기중인 consumer 스레드 깨우기라 했는데.. 비동기 방식이면 굳이 깨우지 않아도 consumer가 들어오길 기다리고 있는거 아니야? await처럼.

C++의 low level 스레드는 직접 제어하지 않으면 무한루프를 돌며 계속 큐가 차있는지 체크하게 됩니다.
ㅇ 이렇게 하면 CPU 점유율이 100%가 되어버립니다.
ㅇ 그래서 consumer 스레드를 완전히 재워두고 producer가 데이터(프레임)를 큐에 넣었을 때 notify_one()으로 consumer 스레드를 깨워줍니다. 이 역할을 하는게 condition_variable입니다.

포인터(*)와 참조(&)의 차이

#include <iostream>

int main() {
	int origin = 100;
	
	// 1. 포인터: origin의 주소를 저장
	int* ptr = &origin;
	
	// 2. 참조자: origin의 또 다른 이름을 부여
	int& ref = origin;
	
	std::cout << origin << std::endl; // 100
	std::cout << *ptr << std::endl; // 100 (*을 붙여서 주소를 찾아감)
	std::cout << ref << std::endl; // 100 (일반 변수처럼 그냥 사용)
	
	// 둘 다 원본을 바꿀 수 있습니다.
	*ptr = 200; // 포인터로 원본 변경
	ref = 300; // 참조자로 원본 변경
	
	std::cout << origin << std::endl; // 300 (원본이 바뀜)
}

가리키는 대상을 바꿀 수 있는가? (가장 큰 차이)
ㅇ 포인터는 메모지라서 내용을 지우고 다른 주소를 새로 적을 수 있습니다.
ㅇ 참조자는 한 번 붙인 이름표라 다른 변수에 다시 붙일 수 없습니다.

int a = 10;
int b = 20;

// 포인터는 대상 변경 가능
int* ptr = &a; // ptr은 a를 가리킴
ptr = &b; // ptr은 이제 b를 가리킴 (대상이 b로 바뀜)

// 참조자는 대상 변경 불가능
int& ref = a; // ref는 a의 별명임.
ref = b; // ref가 b를 가리키게 바뀐 게 아니라, ref(즉 a)에 b의 값(20)을 대입한 것입니다.
// 결과적으로 a의 값이 20으로 바뀝니다.
