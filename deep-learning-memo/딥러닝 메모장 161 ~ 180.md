with 구문을 쓰는 이유

[with 문을 쓰지 않았을 때]
img = Image.open(full_image_path)
img_width, img_height = img.size
# 파일이 여전히 열려있는 상태

ㅇ 위처럼 코드를 짜면 size 정보를 읽은 뒤에도 이미지 파일이 os 메모리상에 계속 열린 채로 남게 된다.
ㅇ 이 상태로 반복문을 돌면..
	Too many open files 에러: 운영체제가 한 프로세스당 동시에 열 수 있는 파일 개수 초과
	메모리 누수: 쓰지 않는 파일 자원이 닫히지 않고 계속 램에 쌓인다.
	파일 잠금 문제: 다른 프로세스가 해당 파일을 수정하거나 삭제하려 할때 "이미 다른 프로그램에서 사용 중입니다"하고 거부당한다.

따라서 with문을 쓰지 않으려면 아래처럼 .close()를 호출해줘야 한다.
img.close()

[with 문을 썼을 때]
with Image.open(full_image_path) as img:
	img_width, img_height = img.size
	# with 블록을 빠져나가는 순간, img.close()를 자동으로 호출해서 파일을 닫는다.

```
yaml_content = yaml.load(f, Loader=yaml.FullLoader)

Loader=yaml.FullLoader: yaml 파일을 읽을 때 보안 위험이 있는 임의의 코드 실행을 막고, 안전하게 파이썬 데이터 타입으로 매핑해주는 로더를 지정한 것임.
결과적으로 yaml_content 안에는 {'train': '', 'val': ''} 같은 딕셔너리가 들어감

print(yaml.dump(yaml_content, default_flow_style=False))
yaml.dump(...): 파이썬 딕셔너리로 바꿨던 yaml_content를 다시 이쁘게 정렬된 yaml 형태의 텍스트로 되돌려 출력합니다.

default_flow_style=False
이 옵션이 없거나 True라면 한줄로 지저분하게 표시됩니다.
False로 설정하면 우리가 보기 편하게 표시됩니다.

```
fig, axes = plt.subplots(2, 4, figsize=(20, 11))

for ax, img_file in zip(axes.ravel(), selected_images):
...


zip(axes.ravel(), selected_images) 뜯어보기

ㅇ axes.ravel()이 하는 일(2차원 -> 1차원 펼치기)

axes = [
  [ax1, ax2, ax3, ax4], 
  [ax5, ax6, ax7, ax8]	
]
axes.ravel()또는 axes.flatten()을 쓰면 2차원을 1차원 리스트로 쫙 펼쳐줍니다.
[ax1, ax2, ax3, ax4, ax5, ax6, ax7, ax8]


ㅇ zip()이 하는 일
여러개의 리스트에서 같은 인덱스에 있는 요소끼리 1:1로 짝을 지어주는 함수입니다.
axes_list = [ax1, ax2, ax3, ax4, ax5, ax6, ax7, ax8] # 8개
selected_images = [img1, img2, img3, ..., img8, img9] # 9개

zip(axes_list, selected_images)를 돌리면
(ax1, img1)
(ax2, img2)
...
(ax8, img8)
그리고 찌끄래기 9번째 사진은 버려집니다.
