1. static constexpr을 쓰는 이유?
ㅇ static: 클래스의 각 객체마다 생기는 게 아닌, 해당 클래스의 모든 객체가 공유하는 전역 상수입니다.

ㅇ constexpr: 컴파일 시점에 값이 확정되는 완벽한 상수임을 보장합니다.
ㅇ 같이 쓰는 이유: C++에서 배열의 크기를 선언할 때(cv::Mat ringBuffer[kCapacity])는 컴파일 시점에 반드시 크기를 알 수 있는 상수여야 합니다.

ㅇ std::memory_order_relaxed (완화된 순서)

일반 변수 int count = 0; 을 들여다 보면, 
우리가 보기엔 count++이 한 줄짜리 명령어 같지만, CPU는 내부적으로 3단계로 나누어 처리합니다.

1. Read: 메모리에 있는 count 값(예: 0)을 CPU 레지스터(임시 저장소)로 읽어옵니다.
2. Modify: 레지스터에 있는 값에 1을 더합니다 (0 + 1 = 1)
3. Write: 더해진 결과(1)를 다시 메모리의 count에 저장합니다.
   
하지만 멀티스레드에서 일반 변수를 쓴다면 다음과 같은 문제가 있습니다.
스레드 A와 B가 동시에 count++을 실행한다고 가정할 때, 다음과 같은 참사가 일어날 수 있습니다.

(1) 스레드 A가 메모리에서 0을 읽음(Read) - count 값: 0
(2) 스레드 B가 메모리에서 0을 읽음(Read) - count 값: 0
(3) 스레드 A가 0 + 1 = 1을 계산(Modify) - count 값: 0
(4) 스레드 B가 0 + 1 = 1을 계산(Modify) - count 값: 0
(5) 스레드 A가 메모리에 1을 씀(Write) - count 값: 1
(6) 스레드 B가 메모리에 1을 씀(Write) - count 값: 1

두 스레드가 각각 1씩 더했으니 결과는 2가 되어야 하지만, 메모리에는 1만 남게 됩니다.

하지만 원자적 변수를 사용하면 Read-Modify-Write 3단계를 하나의 덩어리로 묶어서 처리합니다.

2. if constexpr (컴파일러용 if문)
일반 if문과 달리 컴파일하는 시점에 조건을 판단합니다.

ㅇ 일반 if문: 프로그램이 실행되면서 매번 조건을 검사합니다. 조건이 맞든 틀리든 안쪽 코드는 무조건 컴파일되어 실행 파일에 포함됩니다.

ㅇ if constexpr: 컴파일러가 코드를 빌드할 때 조건을 검사합니다.

컴파일 시점이란?
ㅇ 우리가 짠 영어로 된 소스코드를 0과 1로 이루어진 실행 파일(.exe)로 변환하고 번역하는 과정입니다.

런타임 시점은?
ㅇ 번역이 끝나서 완성된 .exe 파일을 더블클릭해서 실행되는 순간입니다.


근데 일반 if문을 쓰면 컴파일 시점에서는 if문이 true이든 false이든 상관하지 않고 안의 코드를 번역하려고 시도합니다. 그러면.. T에 int가 들어왔을 때 문법이 에러나서 컴파일 에러가 발생합니다.

하지만 if constexpr은 T가 int로 들어오면 컴파일러는 번역하기 전에 미리 조건을 계산합니다.
즉, 최종 만들어지는 실행 파일에서는 이 코드가 존재하지 않는 상태가 됩니다.

결론:
일반 if문은 실행할 때 조건을 검사하므로, 조건이 false여도 컴파일러가 문법 검사(번역)를 해야 해서 에러가 발생합니다.
하지만 if constexpr은 컴파일할 때 조건을 검사해서, 조건이 안 맞으면 코드를 아예 지워버리기 때문에 에러가 나지 않습니다.

allPackets_(집주인): unique_ptr 16개를 꽉 쥐고 있으면서, 프로그램이 시작될 때 힙 메모리에 FramePacket 16개를 만들고 프로그램이 끝날 때 안전하게 delete 해주는 역할만 합니다.
만약 이 벡터가 없다면 누군가 패킷을 빌려 간 상태에서 프로그램이 종료될 때 메모리 누수가 발생할 수 있습니다.

pool_(대여 대장): 현재 놀고 있는(대여 가능한) 패킷들의 주소(열쇠)만 담아두는 대기열입니다.
카메라 스레드가 패킷을 빌려가면 큐에서 열쇠(FramePacket*)를 꺼내주고(pop), 다 쓰고 반납하면 다시 열쇠를 큐에 넣습니다(push). 열쇠만 왔다갔다 할 뿐 실제 객체(allPackets_)는 가만히 있으므로 소유권 이동이나 메모리 할당이 전혀 일어나지 않습니다.
