YOLOv8 모델의 출력 텐서 구조는 [배치 크기, 속성 개수, 앵커 박스 수]로 이루어져 있습니다.

1 (Batch size): 한번에 밀어넣은 이미지 개수

5 (Attributes / Info): 박스 1개단 들어있는 정보의 개수(5개)

8400개의 박스에 각각 5개의 정보가 있다면 (1, 8400, 5) 순서가 되어야 하는게 아닌가?

딥러닝 모델 내부에서 행렬 연산을 할 때는 메모리 연속성(Contiguous Memory) 문제 때문에 채널(정보/속성) 차원을 앞쪽에 두는 형태 (Batch, Channels, Anchors)가 GPU 입장에서 연산속도가 빠릅니다.

그래서 우리는 이걸 전치(np.transpose() 또는 .T)를 해줍니다.

[파이썬 코드]

# 맨 앞 배치 차원 제거

# 전치시켜서 (8400, 5)로 변환
predictions = outputs_2d.T # 또는 np.transpose(outputs_2d)

print(predictions.shape) # (8400, 5)

뒤 글자 (Positive / Negative): 모델이 물체가 있다(P)고 했는가, 없다(N)고 했는가?
앞 글자 (True / False): 모델의 그 예측이 맞았나(T), 틀렸나(F)?

사진 속에 진짜 사과 3개와 붉은색 양파 1개가 있다고 가정하자.
우리는 사과를 찾는 모델을 만들었다.

1. TP - 있다고 했는데 정답임 (진짜 정답)
   의미: 모델이 여기 있다(Positive)라고 했는데, 진짜로 정답(True)인 경우
   예시: 진짜 사과를 보고 사과라고 네모박스 친 경우

2. FP - 있다고 했는데 오답임 (가짜 정답)
   의미: 모델이 여기 있다(Positive)라고 했는데, 실제로는 오답(False)인 경우
   예시: 붉은색 양파를 보고 사과라고 네모박스 친 경우

3. FN - 없다고 했는데 오답임 (놓친 정답)
   의미: 모델이 "여긴 아무것도 없다(Negative)"라고 했는데, 실제로는 사과가 있음. 즉, 모델이 틀림(False)
   예시: 진짜 사과가 있는데, 모델이 네모박스 치지 않고 그냥 지나친 경우

4. TN - 없다고 했는데 진짜 없음(정답) (정상 제외)
   의미: 모델이 "여긴 아무것도 없다(Negative)"라고 했는데, 실제로도 사과가 없었음. 사과가 없는 배경이라서 모델이 맞힘(True)
   참고: 객체 탐지(YOLO)에서는 사과가 없는 빈 배경이 무한히 많기 때문에, 사실상 TN의 개수는 의미가 없습니다.
   

[1] Precision - TP / (TP + FP)
의미: 모델이 "사과야!"라고 예측한 것들 전체(TP + FP) 중에서, 진짜 사과(TP)의 비율

[2] Recall - TP / (TP + FN)
의미: 사진 속에 존재하는 진짜 사과 전체(TP + FN) 중에서, 모델이 놓치지 않고 찾아낸 사과(TP)의 비율

fitness는 모델의 종합 성적표 점수이다.
여러 가지 평가지표(Precision, Recall, mAP 등)를 YOLO 내부 공식에 따라 종합적으로 계산한 점수이다.

fitness가 필요한 이유
학습을 진행할 때 컴퓨터는 어떤 에폭 또는 어떤 파라미터 조합이 가장 최고인가?를 판단해야 한다.
	Precision이 높지만 Recall이 낮을 수도 있고, 반대로 mAP50은 높은데 mAP50-95는 낮을 수 있다.
	이렇게 지표들이 엇갈릴 때, 하나의 절대적인 기준이 필요한데, 그것이 바로 fitness인 것이다.

fitness 계산법
fitness = (0.1 * mAP50(B)) + (0.9 * mAP50-95(B))
Precision과 Recall은 반영되지 않으며, 기준이 널널한 mAP50에는 10%, 기준이 엄격한 mAP50-95에는 90%의 비중을 두어 계산합니다.

shutil 라이브러리 복사 함수(copyfile(), copy(), copy2())의 차이

1. shutil.copyfile(src, dst): 순수한 내용물만 빠르게
   동작: 파일의 내용(데이터)만 복사합니다. 파일 권한이나 생성/수정 시간 같은 메타데이터는 모두 무시합니다.
   추천 용도: 대용량 동영상/이미지 파일을 가장 가볍고 빠르게 복사할 때 씁니다.

2. shutil.copy(src, dst): 폴더 안으로 쏙 넣기
   동작: 파일 내용물과 함께 실행 권한(r/w/x)까지 함께 복사합니다.
   장점: 목적지(dst)에 파일명 대신 폴더 경로만 지정해도 작동합니다. 폴더 경로만 주면 원본 파일 이름을 그대로 유지한 채 복사해 줍니다.
   추천 용도: 여러 파일을 특정 작업용 폴더로 뭉탱이로 복사할 때 파일명을 일일이 지정할 필요가 없어서 편리합니다.

3. shutil.copy2(src, dst): 메타데이터까지 완벽한 복제본
   동작: copy()의 기능에 더해, 파일 생성 시간, 수정 시간 등 메타데이터까지 원본 그대로 보존하여 복사합니다.
   추천 용도: 데이터셋 백업, 로그 파일 보관 등, "파일이 언제 만들어졌고 수정되었는지" 알 필요가 있는 중요한 작업을 할 때 사용합니다.
