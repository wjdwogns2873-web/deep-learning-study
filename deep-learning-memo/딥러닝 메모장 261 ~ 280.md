PyTorch의 프레임워크 오버헤드

1. 파이썬 중심의 실행 구조
PyTorch는 개발자가 사용하기 편한 파이썬 API를 제공합니다. 하지만, 추론을 할 때마다 파이썬 인터프리터가 개입하게 됩니다.
ㅇ 파이썬 런타임 오버헤드: 연산 자체는 C++로 구현되어 있더라도, 각 연산을 호출하고 제어하는 과정에서 파이썬 레이어의 오버헤드(GIL, 동적 타이핑)가 발생합니다.
ㅇ 레이턴시 손해: ms 단위를 다루는 실시간 서비스 환경에서는 이 미세한 오버헤드가 큰 영향을 미칩니다.

2. 동적 계산 그래프
PyTorch의 가장 큰 장점은 코드가 실행될 때마다 그래프가 새로 빌드되는 방식입니다.
ㅇ 디버깅 & 모델 수정은 편리하지만, 추론할 때도 매번 다음 연산이 무엇인지 확인하고 메모리를 할당하는 과정을 거쳐야 하므로 불필요한 연산 낭비가 생깁니다.
ㅇ 반면 TensorRT는 정적 계산 그래프 형태로 바꾸어 최적화합니다.

3. 커널 호출 오버헤드
PyTorch에서 모델을 실행하면 수많은 연산(Conv, ReLU 등)이 GPU 커널을 각각 따로 호출합니다.
ㅇ GPU는 연산이 빠르지만, CPU가 GPU에게 명령하는 커널 호출 자체에도 시간이 걸립니다.
ㅇ 연산이 수백 개 엮여 있으면 커널 호출 오버헤드만으로도 시간이 소요됩니다. TensorRT는 이를 하나로 뭉치는 커널 융합을 통해 이 오버헤드를 줄입니다.

노드와 레이어의 차이

레이어는 층의 개수이고, 노드는 그 층을 구성하는 개별 계산기의 개수

예를 들어 3개의 레이어로 이루어진 신경망이고, 각 레이어의 차원이 128이다 라고 한다면..
레이어는 3개이고, 총 노드의 개수는 3 * 128 = 384개가 됩니다.

Dropout에서 "노드를 끈다"라는 말의 의미.

out_features=64인 레이어에 드롭아웃(0.5)을 걸면 64개의 출력값 중 랜덤하게 32개를 골라 강제로 0으로 바꿉니다. (예: [1.5, -0.2, 3.1] -> [1.5, 0, 3.1])

출력값이 0이 되면..
1. 순전파: 다음 레이어로 0이 전달되므로, 다음 레이어의 연산에 아무런 영향을 주지 못합니다.
2. 역전파: 0으로 바뀐 자리는 미분을 해도 기울기가 0이 됩니다. 즉, 그 노드와 연결된 가중치들은 이번 턴에 전혀 업데이트되지 않고 멈춥니다.

ㅇ engine.get_tensor_shape 결과에 tuple()로 감싸야 했던 이유

최신 TensorRT에서 engine.get_tensor_shape()은 tuple이나 list를 반환하지 않고 TensorRT 내부 객체와 연결된 Dims 클래스 객체를 반환합ㄴ디ㅏ.
하지만 cuda.pagelocked_empty() 함수는 NumPy나 PyCUDA 기반이라서 반드시 tuple이나 list 형태의 shape으로만 인자를 받아야 합니다.

ㅇ pagelocked_empty의 의미
CPU 메모레를 할당할 때, "이 메모리는 절대 디스크로 페이지 아웃시키지 말고, RAM에 딱 고정시켜줘"라고 요청합니다.
Pinned Memory(고정 메모리)라고도 합니다.

ㅇ 일반 메모리(np.empty)
컴퓨터는 RAM이 부족해지면 당장 안 쓰는 메모리를 하드디스크로 잠시 빼둡니다(Page-Out)
이 상태에서 GPU로 데이터를 보내려고 하면, 컴퓨터는 [디스크->RAM으로 다시 가져오기->GPU로 전송]이라는 단계를 거쳐야 해서 전송 속도가 느려집니다.

ㅇ 고정 메모리(cuda.pagelocked_empty)
이 데이터는 딥러닝 추론용이니 절대 디스크로 쫓아내지 말고 RAM에 고정시켜줍니다.
이렇게 하면 속도가 빨라집니다.

np.ascontiguousarray(): GPU 메모리에 데이터를 한 번에 초고속으로 복사하기 위해, 데이터들을 메모리상에 빈틈없이 한줄로 나란히 정렬하기 위함.

이렇게 하는 이유?
transpose를 할 때 NumPy는 계산 속도를 아끼기 위해 실제 메모리에 있는 데이터의 위치를 뒤바꾸지 않습니다.
겉보기(shape)만 바꾸고, 데이터를 읽는 순서의 규칙만 수정합니다.
물리적 실제 메모리: 여전히 원래 이미지의 순서인 [R1, G1, B1, R2, G2, B2...]로 되어있습니다.
파이썬의 눈속임: R1, R2...], [G1, G2...], [B1, B2...]인 것처럼 속여서 보여줍니다.

이렇게 실제 데이터가 주소대로 나란히 있지 않고 듬성듬성 떨어져 있는 상태를 Non-contiguous(비연속성) 상태라고 합니다.

이 상태 그대로 GPU로 전송(cuda.memcpy_htod_async)하려고 하면 문제가 생깁니다.
GPU로 데이터를 쏘아 보내는 하드웨어 가속 장치는 "메모리 특정 주소부터 특정 주소까지 빈틈없이 이어져 있는 덩어리"만 한 번에 초고속 복사 가능합니다. 징검다리로 있다면 에러가 나거나 속도가 엄청 느려집니다.

np.ascontiguousarray()의 역할
넘파이는 눈속임을 하지 않고 실제 물리 메모리를 새로 파서 데이터를 순서대로 한 줄로 이쁘게 정렬해 줍니다.
이렇게 하면 GPU로 초고속 전송이 가능합니다.

np.copyto(목적지, 원본)
pinned_buf(h_input)는 함수 외부에서 cuda.pagelocked_empty를 통해 이미 메모리상에 빈틈없이 예쁘게 만들어진 고정 메모리 방입니다.
np.copyto 함수는 원본 데이터(tensor)가 징검다리처럼 되어있든 상관없이, 데이터를 하나씩 읽어와서 목적지(pinned_buf)에 채워 넣을 때 차곡차곡 정렬하면서 집어넣습니다.
