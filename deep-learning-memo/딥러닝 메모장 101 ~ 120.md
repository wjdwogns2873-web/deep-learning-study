for epoch in range(epochs):
	# ...학습 및 검증 진행...
	
	# 이번 에폭의 val_loss가 최고 기록을 갱신했는지 확인
	if current_val_loss < best_val_loss:
		best_val_loss = current_val_loss
		patience_counter = 0 # 갱신했으니 초기화

	else:
		patience_counter += 1 # 갱신 실패했으니 카운트 증가

가중치 동결이 오히려 성능을 깎아먹는 이유

- 가중치 동결했을 때 (96~97%)
ResNet18의 뼈대를 그대로 얼려두면 이 모델은 "일반적인 세상의 모든 사물을 다 잘 알아보는 뇌" 상태로 고정됨.
그 상태에서 맨 마지막 레이어(model.fc)만 바꾸고 학습시키면 원래 가지고 있던 일반적인 시각 능력만 가지고 구별해야 한다.
하지만 ImageNet에는 갈변부분 같은 아주 미세한 특징이 깊게 학습되어 있지 않다.
즉, 뼈대가 과일의 디테일을 잡기엔 너무 둔감했다.

- 가중치 동결하지 않았을 때 (99.76%)
모든 가중치를 열어두고 학습(파인튜닝)시키면 ResNet18이 가진 수천만개의 가중치가 과일의 신선도를 위해 통째로 재설계된다.


실무에서 가중치 동결 여부를 결정하는 기준
(1) 가중치 동결이 유리할 때: 데이터가 너무 적어서 전체를 학습시키면 과적합이 일어나거나, 컴퓨터 사양이 너무 낮아서 빠른 학습이 필요할 때

(2) 전체 파인튜닝이 유리할 때: 지금처럼 데이터 수가 충분하고, 맞추고자 하는 목표가 기존 이미지넷 데이터와 성격이 조금 달라서 모델의 가중치들을 미세하게 조정해줄 필요가 있을 때


그렇다면.. 현업에서는 가중치 동결을 거의 하지 않는건가? 그렇지 않다.
현업의 데이터는 매우 불균형하고 더럽기 때문이다.
제조업 공장 라인에서 '정상 제품'은 수만 장씩 쏟아지지만, '불량 제품'은 엄청 드물다.

동결이 필요한 이유: 데이터가 수만장 있어도 데이터 불균형이 있으면 전체 가중치를 열어놓고 학습할 때 모델이 정상 데이터에만 과적합되는 문제가 발생할 수 있다.
이럴 때 기존의 사물의 형태를 잘 파악하도록 훈련된 백본 모델의 가중치를 동결해 두고, 뒤쪽 분류기(fc)만 영리하게 학습시켜서 모델의 기본 시각 능력이 망가지는 걸 방지한다.

```
F1-Score는 최저 0.0에서 최고 1.0 사이의 값을 가진다.
- 정밀도(Precision)와 재현율(Recall)이 모두 완벽하게 100%일 때, 1.0이 나온다.
  
(1) Macro F1
평가 방식: 각 클래스의 f1-score를 각각 구한 뒤, 데이터 개수와 상관없이 N분의 1(평균)을 합니다.
특징: 데이터가 적은 클래스도 많은 클래스와 똑같은 무게(가치)로 취급합니다.
데이터 불균형이 심할 때, 소수 클래스를 얼마나 잘 맞혔는지 평가하고 싶을 때 씁니다.

(2) Micro F1
평가 방식: 클래스를 다 무시하고, 전체 데이터셋을 통틀어서 총 맞힌 개수, 총 틀린 개수를 다 합쳐서 계산합니다.
특징: 다중 분류에서 Micro F1을 계산하면 우리가 흔히 아는 정확도(Acc)와 수학적으로 완전히 같은 값이 나옵니다.
클래스 구분 없이 전체적으로 모델이 얼마나 많이 맞혔는지 총량이 중요할 때 씁니다.

(3) Weighted F1
평가 방식: 각 클래스의 f1-score를 구한 뒤, 각 클래스의 데이터 개수 비율(가중치)을 곱해서 평균을 냅니다.
특징: 데이터가 많은 클래스의 성적이 점수에 큰 영향을 미칩니다.
소수 클래스가 틀리는 것보다, 현실적인 전체 데이터 분포의 비율을 반영한 성적을 보고싶을 때 씁니다.
```

이미지 분류에서 되던 images.to(device)가 객체 탐지에서는 안되는 이유.

이미지 분류에서 가능했던 이유:
이미지 분류에서는 모든 이미지의 규격(정방향 행렬)이 같고, 라벨도 단순한 단일숫자(스칼라)이기 때문이다.

객체 탐지에서 안되는 이유:
이미지마다 포함된 네모박스의 개수가 제각각 다르다. 이로 인해 스택(stack) 연산이 불가능하여, collate_fn을 통해 데이터를 하나의 텐서가 아닌 '파이썬 리스트(또는 튜플)' 구조로 묶어 전달했다.
파이토치 텐서와 달리 파이썬 리스트 객체는 .to(device) 라는 메서드를 가지고 있지 않기 때문에 에러가 발생한다. 따라서 루프 내부에서 리스트 컴프리헨션을 통해 개별 텐서 요소들을 일일이 하나씩 꺼내서 device로 이동시켜줘야 한다.
