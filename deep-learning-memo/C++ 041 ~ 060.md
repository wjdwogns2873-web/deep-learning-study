std::string&& : &가 두 개인 이유.

ㅇ const std::string& (기존 방식): 읽기 전용이므로 함수 내부에서 메시지를 저장하거나 다른 곳으로 옮기려면 깊은 복사를 해야 합니다. (복사 비용 발생)
ㅇ std::string&& (이동 방식): 이 메시지 데이터는 어차피 함수 호출 끝나면 버려질 임시 객체니까, 복사하지 말고 std::move()로 내부 포인터 소유권만 뺏아간다.는 뜻입니다. (복사 비용 0)

ㅇ 일반 전역 변수 (static 없음): 다른 파일과 공유 가능

// file_A.cpp
int global_value = 10; // 일반 전역 변수

// file_B.cpp
#include <iostream>

extern int global_value; // file_A에 있는 변수를 링크하여 사용

void printValue() {
	std::cout << global_value << std::endl; // 출력: 10
}


ㅇ static 전역 변수: 현재 파일에서만 독점적으로 사용

//file_A.cpp
static int hidden_value = 20;
