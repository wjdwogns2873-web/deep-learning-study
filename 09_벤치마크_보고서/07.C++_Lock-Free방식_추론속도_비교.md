# C++ TensorRT: FP32 vs FP16 vs INT8 동영상 스트리밍 벤치마크 보고서 (lock-free 방식)


## 📊 종합 성능 비교 요약

| 정밀도 엔진 | 평균 Latency (Avg) | 최소 Latency (Min) | 최대 Latency (Max) | 평균 처리 속도 (FPS) |
| :--- | :--- | :--- | :--- | :--- |
| **1. FP32** | **11.88 ms** | **7.91 ms** | **37.56 ms** | **84.1 FPS** |
| **2. FP16** | **10.70 ms** | **7.13 ms** | **30.73 ms** | **93.5 FPS** |
| **3. INT8** | **10.84 ms** | **7.29 ms** | **30.92 ms** | **92.3 FPS** |

---

이번엔 C++ TensorRT 환경에서 YOLOv8n 모델의 정밀도별로 lock-free 방식으로 동영상 스트리밍 속도를 비교해 보았습니다.

본격적 추론하기 전에, Warm-up. 예열 과정 없이 추론했을 때는 max latency가 137.75ms에서 213.75 ms까지 웃도는 것을 확인하고, 

"아, warm-up 과정이 무조건 있어야, 정밀하게 평가가 가능하겠구나"라는 생각을 했습니다.

그러면.. 왜 Warm-up이 없으면 초반에 latency가 튀는 현상을 보이는가? 이유는 몇가지가 있습니다.

TensorRT 엔진 파일(.engine)을 메모리에 올린 직후, 첫 프레임이 GPU에 올라가는 순간 내부에서는 엄청난 양의 초기화 작업이 일어납니다.

먼저, GPU 내부 연산 코어들과 메모리 제어권을 초기화하고 연결하는 드라이버 연산이 최초 1회 작동하고, 
사용할 GPU 가상 메모리 주소를 매핑하는 부하가 발생합니다.

이러한 오버헤드가 첫 번째 프레임의 추론 시간에 고스란히 누적되기 때문입니다.

---

다시 본론으로 돌아와서, 이전에 했던 비동기 멀티스레드도 괜찮았지만, 그 방식은 producer가 프레임을 넣을 때(push) 문을 잠그고, 

consumer가 꺼낼 때(pop) 문을 잠급니다. 만약 그 타이밍이 겹치면 한쪽 스레드는 동작을 멈추고 기다려야 하는 병목이 생길 수 있습니다.

하지만 지금의 lock-free 구조는 std::atomic을 사용하여 mutex라는 자물쇠를 쓰지 않고도 스레드가 데이터를 안전하게 주고받을 수 있게 합니다.
스레드가 자물쇠 때문에 기다리는 시간이 0ms가 되기 때문에, 성능을 극한으로 끌어올릴 수 있습니다.

요약 표를 보시면, 이전 멀티스레드 mutex 방식에 비해 얼마나 성능 향상이 되었는지 확인할 수 있습니다.

멀티스레드 mutex 방식은 71.9 FPS가 맥시멈으로, 70대를 머무는 한계가 있었습니다.

👉 [멀티스레드 mutex 방식 보러 가기](https://github.com/wjdwogns2873-web/deep-learning-study/blob/main/09_%EB%B2%A4%EC%B9%98%EB%A7%88%ED%81%AC_%EB%B3%B4%EA%B3%A0%EC%84%9C/C%2B%2B_%EC%96%91%EC%9E%90%ED%99%94_%EB%AA%A8%EB%8D%B8_%EB%B9%84%EA%B5%90(%EB%B9%84%EB%8F%99%EA%B8%B0_%EB%A9%80%ED%8B%B0%EC%8A%A4%EB%A0%88%EB%93%9C).md)


하지만 지금 lock-free 방식은 모든 정밀도 엔진 면에서 mutex 방식을 압도합니다.

FP16 정밀도는 평균 FPS가 무려 93.5에 달합니다.

결과적으로 mutex 방식의 구조적 한계(타이밍이 겹치면 한쪽 스레드가 기다려야 하는 상황)를 극복하고, 성능을 극한으로 끌어올림으로서
C++ 설계의 중요성을 깨달았습니다.

### `builder_all.cpp(engine 파일 생성)`
```cpp
#include <iostream>
#include <fstream>
#include <memory>
#include <vector>
#include <string>
#include <algorithm>
#include <cstdint>
#include <NvInfer.h>
#include <NvOnnxParser.h>

// TensorRT는 Logger를 기본으로 내장하지 않고 사용자게에 구현을 하도록 강제합니다.
// TensorRT 엔진 빌드 및 추론 과정에서 발생하는 경고나 에러 메시지를 출력하기 위한 Logger입니다.
class Logger : public nvinfer1::ILogger {
    void log(Severity severity, const char* msg) noexcept override {
        if (severity <= Severity::kWARNING) {
            std::cout << "[TensorRT] " << msg << std::endl;
        }
    }
} gLogger;

int main() {
    // FP32, FP16, INT8 정밀도별로 변환할 모델 이름을 리스트로 정의합니다.
    std::vector<std::string> models = { "yolov8n.fp32", "yolov8n.fp16", "yolov8n.int8" };

    for (const auto& modelName : models) {
        std::cout << "\n모델명: " << modelName << std::endl;

        // Builder를 생성합니다.
        // TensorRT 엔진을 최적화하고 빌드하기 위한 빌더 객체를 생성합니다.
        nvinfer1::IBuilder* builder = nvinfer1::createInferBuilder(gLogger);
        if (!builder) {
            std::cerr << "Builder 생성 실패: " << modelName << std::endl;
            continue;
        }

        // Network를 생성합니다.
        // 신경망 그래프 구조를 담을 Network를 생성합니다. 플래그가 0이면 기본 설정이라는 의미입니다.
        nvinfer1::INetworkDefinition* network = builder->createNetworkV2(0);
        if (!network) {
            std::cerr << "Network 생성 실패" << std::endl;
            delete builder;
            continue;
        }

        // ONNX Parser 생성 및 모델 파싱
        // ONNX 파일 구조를 읽어와서 TensorRT 네트워크 정의로 변환(Parsing)합니다.
        nvonnxparser::IParser* parser = nvonnxparser::createParser(*network, gLogger);
        std::string onnxPath = modelName + ".onnx";
        std::cout << onnxPath << " 생성중.." << std::endl;
        if (!parser->parseFromFile(onnxPath.c_str(), static_cast<int>(nvinfer1::ILogger::Severity::kWARNING))) {
            std::cerr << "ONNX 파싱 실패" << onnxPath << std::endl;
            delete parser;
            delete network;
            delete builder;
            continue;
        }

        // Config 생성
        // 최적화 옵션을 설정하기 위한 Config를 생성합니다.
        nvinfer1::IBuilderConfig* config = builder->createBuilderConfig();
        
        // TensorRT 직렬화합니다.
        // 설정된 Config와 Network를 바탕으로 타겟 GPU 하드웨어에 맞게 최적화된 엔진을 빌드합니다.
        // 이 과정에서 GPU 커널 최적화가 일어나기 때문에 시간이 좀 소요됩니다.
        std::cout << "최적화 컴파일 가동중.." << std::endl;
        nvinfer1::IHostMemory* plan = builder->buildSerializedNetwork(*network, *config);

        if (!plan) {
            std::cerr << "최적화 엔진 변환 실패: " << modelName << std::endl;
            delete config;
            delete parser;
            delete network;
            delete builder;
            continue;
        }

        // 바이너리 파일로 저장하기 위해 준비합니다.
        std::string enginePath = modelName + ".engine";
        std::ofstream engineFile(enginePath.c_str(), std::ios::binary);
        if (!engineFile) {
            std::cerr << "엔진 파일 생성 권한 오류: " << enginePath << std::endl;
            delete plan;
            delete config;
            delete parser;
            delete network;
            delete builder;
            continue;
        }
        // 엔진 파일(.engine)로 저장합니다.
        engineFile.write(reinterpret_cast<const char*>(plan->data()), plan->size());
        engineFile.close();

        std::cout << "저장 완료: " << enginePath << " (" << plan->size() << " bytes)" << std::endl;

        // 다음 정밀도 모델을 위해 안전하게 자원을 해제합니다. 메모리 누수 방지!
        delete plan;
        delete config;
        delete parser;
        network->~INetworkDefinition(); // 최신 TensorRT 규격에 맞춘 안전한 소멸자를 호출합니다.
        delete builder;
    }

    std::cout << "\n모든 정밀도 엔진 빌드가 종료되었습니다" << std::endl;
    return 0;
}
```

### `YoloTRT.h`
```cpp
#ifndef YOLO_TRT_H
#define YOLO_TRT_H

#include <iostream>
#include <fstream>
#include <vector>
#include <string>
#include <algorithm>
#include <opencv2/opencv.hpp>
#include <NvInfer.h>
#include <cuda_runtime_api.h>
#include <filesystem>

// 탐지된 박스 정보를 표현할 Detection 구조체를 선언합니다.
struct Detection {
    cv::Rect box; // xmin, ymin, width, height를 담을 box
    float confidence; // 확신도를 담을 confidence
    int classId; // 클래스 아이디를 담을 classId
};

// TensorRT에서는 Logger 구현이 필수적입니다.
// TensorRT 엔진 빌드 및 추론 과정에서 발생하는 경고나 에러 메시지를 출력하기 위한 Logger입니다.
class TRTLogger : public nvinfer1::ILogger {
    void log(Severity severity, const char* msg) noexcept override {
        if (severity <= Severity::kWARNING) {
            std::cout << "[TensorRT] " << msg << std::endl;
        }
    }
};

class YoloTRT {
public:
    YoloTRT(const std::string& enginePath);
    ~YoloTRT();

    // 실제로 추론할 detect 함수를 선언합니다.
    // 이미지, conf 임계값과 nms 임계값을 매개변수로 받아서 std::vector<Detection>을 반환합니다.
    std::vector<Detection> detect(const cv::Mat& srcImg, float confThresh = 0.25f, float nmsThresh = 0.45f);

    void inferOnly();

private:
    TRTLogger gLogger;
    // nvinfer1이 인터페이스라서 인스턴스를 직접 생성할 수 없기 때문에 오직 포인터로만 다뤄야 합니다.
    nvinfer1::IRuntime* runtime = nullptr;
    nvinfer1::ICudaEngine* engine = nullptr;
    nvinfer1::IExecutionContext* context = nullptr;
    
    // 전처리 함수입니다. 640 640 리사이즈, HWC to CHW, BGR to RGB 등의 전처리 작업을 수행합니다.
    void preprocess(const cv::Mat& srcImg);

    // 후처리 함수입니다. 원본이미지로 복원하는 과정, nms 작업 등이 있습니다.
    std::vector<Detection> postprocess(int origW, int origH, float confThresh, float nmsThresh);

    cudaStream_t stream = nullptr;

    // Device(GPU)의 입출력 포인터(주소값)입니다.
    void* d_input = nullptr;
    void* d_output = nullptr;

    // Host(CPU)의 입출력 포인터(주소값)입니다.
    float* h_input = nullptr;
    float* h_output = nullptr;

    // 입출력 텐서의 메모리 크기입니다.
    size_t inputSize = 1 * 3 * 640 * 640 * sizeof(float);
    size_t outputSize = 1 * 84 * 8400 * sizeof(float);

    // 동적으로 메모리 할당 및 해제를 방지하기 위해 최초 한 번만 생성합니다.
    std::vector<cv::Rect> boxes; // 탐지된 네모박스 정보(cv::Rect)를 담기 위해 std::vector<cv::Rect>를 선언합니다.
    std::vector<float> confidences; // 네모박스들의 확신도를 담기 위해 std::vector<float>을 선언합니다.
    std::vector<int> classIds; // 네모박스들의 클래스 아이디를 담기 위해 std::vector<int>를 선언합니다.
    std::vector<int> indices; // conf, nms 임계값을 넘은 네모박스들의 임계값을 담을 std::vector<int>를 선언합니다.
};

#endif // YOLO_TRT_H
```

### `YoloTRT.cpp`
```cpp
#include "YoloTRT.h"
namespace fs = std::filesystem;

YoloTRT::YoloTRT(const std::string& enginePath) {
    // 1. 바이너리 엔진 파일 읽기
    std::ifstream file(enginePath, std::ios::binary);
    if (!file.good()) {
        std::cerr << "엔진 파일을 찾을 수 없습니다: " << enginePath << std::endl;
        return; 
    }
    file.seekg(0, file.end); // file 커서를 맨 끝(end)으로 이동합니다.
    size_t size = file.tellg(); // 현재 커서의 위치(end)는 파일의 전체 바이트 크기를 의미하므로, 이것을 변수로 저장합니다.
    file.seekg(0, file.beg); // file 커서를 다시 맨 처음(beg)으로 이동합니다.

    std::vector<char> engineData(size); // file의 크기만큼의 빈 공간을 가진 1차원 벡터를 생성합니다.
    // 벡터가 메모리에 할당된 시작 주소(engineData.data())를 통해,
    // file에 들어있던 바이너리 데이터를 그 시작 주소로부터 size만큼 통째로 읽어와서 복사합니다.
    file.read(engineData.data(), size);
    file.close();

    runtime = nvinfer1::createInferRuntime(gLogger);
    // engineData에는 .engine 파일의 바이너리가 1차원 벡터로 담겨 있는데, .data()를 써서 그 1차원 주소의 시작값ㅇ르 가져옵니다.
    // 주소 시작값부터 size만큼의 데이터를 역직렬화해서 엔진을 생성합니다.
    engine = runtime->deserializeCudaEngine(engineData.data(), size);
    context = engine->createExecutionContext();

    // GPU에서 CPU로 데이터를 전송할 통로(Stream)를 생성합니다.
    cudaStreamCreate(&stream);

    // inputSize, outputSize만큼의 메모리를 미리 동적으로 할당합니다.
    // 그리고 할당된 메모리의 시작 주소를 d_input, d_output에 담아줍니다.
    // &로 하지 않으면 그냥 값만 넘겨주고, 주소를 넘겨주지 못하기 때문에 d_input에는 아무런 변화가 없습니다.
    // 그래서 &d_input으로 넘겨줘야, 문신처럼 새길 수 있습니다.
    cudaMalloc(&d_input, inputSize);
    cudaMalloc(&d_output, outputSize);

    // cudaHostAlloc(): CUDA에서 Pinned memory를 Host(CPU) 측에 할당하는 함수입니다.
    // 일반적으로 malloc()을 통해 할당한 메모리는 OS에 의해 디스크로 페이징(메모리스왑)이 될 수 있는 pageable memory입니다.
    // 반면 cudaHostAlloc()으로 할당된 메모리는 물리 RAM에 고정할(Pinned) 수 있으므로, GPU가 Host Memory에 빠르게 접근할 수 있습니다.
    // 여기서 &로 넘겨주는 이유도 위와 마찬가지로, 문신처럼 새기기 위함입니다.
    // (void**)는 CUDA 함수와 타입을 맞추기 위한 강제 형변환인데,
    // cudaHostAlloc은 사용자가 메모리에 float을 담을지, int를 담을지 알 수 없으므로 어떤 포인터 주소든 다 받을 수 있도록 강제 형변환합니다.
    cudaHostAlloc((void**)&h_input, inputSize, cudaHostAllocDefault);
    cudaHostAlloc((void**)&h_output, outputSize, cudaHostAllocDefault);

    // 각 벡터 안에는 최대 8400개의 탐지된 네모박스의 데이터가 들어올 수 있으므로 미리 메모리 공간을 예약(reserve)합니다.
    boxes.reserve(8400);
    confidences.reserve(8400);
    classIds.reserve(8400);
    indices.reserve(8400);

    const char* inputName = engine->getIOTensorName(0);
    const char* outputName = engine->getIOTensorName(1);
    // 모델의 입력과 출력 데이터가 실제로 저장될 메모리 주소(d_input, d_output)를 매핑해 줍니다.
    context->setTensorAddress(inputName, d_input);
    context->setTensorAddress(outputName, d_output);
}

YoloTRT::~YoloTRT() {
    // 추론이 끝나면, 메모리 누수를 막기 위해 모든 자원을 반납하여 할당 해제합니다.
    if (stream) cudaStreamDestroy(stream);
    if (d_input) cudaFree(d_input);
    if (d_output) cudaFree(d_output);

    if (h_input) cudaFreeHost(h_input);
    if (h_output) cudaFreeHost(h_output);

    if (context) delete context;
    if (engine) delete engine;
    if (runtime) delete runtime;
}

// 전처리 함수입니다.
void YoloTRT::preprocess(const cv::Mat& srcImg) {
    cv::Mat resizedImg;
    cv::resize(srcImg, resizedImg, cv::Size(640, 640)); // 640 640 크기로 리사이즈합니다.
    cv::cvtColor(resizedImg, resizedImg, cv::COLOR_BGR2RGB); // BGR을 RGB 순서로 바꿉니다.

    cv::Mat floatImg;
    resizedImg.convertTo(floatImg, CV_32FC3, 1.0 / 255.0); // 0~1의 실수값으로 정규화합니다.

    int channelSize = 640 * 640;
    // reinterpret_cast: 이 메모리 주소의 해석 방식을 강제로 바꿔라는 뜻입니다.
    // cv::Mat 객체(floatImg)의 내부 데이터의 실제 주소는 uchar* 형태입니다.
    // 이 메모리 주소를 float* 형식을 가진 포인터로 취급해서, 앞으로 실수 단위로 값을 꺼내 쓸 수 있도록 해달라고 타입을 변환합니다.
    float* data = reinterpret_cast<float*>(floatImg.data);

    // [R0, G0, B0, R1, G1, B1, ...]를 [R0, R1, ..., G0, G1, ..., B0, B1, ...]로 바꿉니다.
    // 그러면 HWC가 CHW로 바뀝니다. (640, 640, 3) -> (3, 640, 640)
    for (int i = 0; i < channelSize; ++i) {
        h_input[i]                   = data[i * 3 + 0]; // R
        h_input[i + channelSize]     = data[i * 3 + 1]; // G
        h_input[i + channelSize * 2] = data[i * 3 + 2]; // B
    }
}

// 후처리 함수입니다.
std::vector<Detection> YoloTRT::postprocess(int origW, int origH, float confThresh, float nmsThresh) {
    // 이전 프레임 때 사용했던 네 개의 벡터들을 깔끔하게 비워주고, 재사용합니다.
    boxes.clear();
    confidences.clear();
    classIds.clear();
    indices.clear();

    // 전처리 과정에서 원본 이미지를 640 640 크기로 리사이즈하는 과정이 있었기에, 탐지된 네모박스도 640 640 이미지 기준입니다.
    // 이것을 원본 사이즈로 복원하는 과정이 필요한데,
    // 원본 이미지의 가로 세로 길이를 각각 640으로 나눈 뒤에 그 값을 scaleX, scaleY로 저장합니다.
    // 나중에 rectangle하기 전에 이값을 곱해주어 원본 크기로 복원하기 위함입니다.
    float scaleX = static_cast<float>(origW) / 640.0f;
    float scaleY = static_cast<float>(origH) / 640.0f;

    // 탐지된 8400개의 박스에 대해 반복문을 실행합니다.
    for (int i = 0; i < 8400; i++) {
        // h_output은 (1, 84, 8400) 데이터를 일렬로 가지고 있고, 앞 4개(0~3)는 cx, cy, bw, bh를 가지고 있습니다.
        float cx = h_output[0 * 8400 + i];
        float cy = h_output[1 * 8400 + i];
        float w  = h_output[2 * 8400 + i];
        float h  = h_output[3 * 8400 + i];

        // 각 80개의 클래스 중에서 확신도가 가장 높은 클래스 아이디와, 그 클래스의 확신도 값을 가져오는 로직입니다.
        float maxScore = 0.0f;
        int maxClassId = -1;
        // 뒤 80개(4~83)는 클래스 아이디를 의미합니다.
        for (int c = 0; c < 80; c++) {
            float score = h_output[(c + 4) * 8400 + i];
            if (score > maxScore) {
                maxScore = score;
                maxClassId = c;
            }
        }

        // 가장 높은 확신도를 가진 클래스의 확신도가 conf 임계값을 넘었을 때의 박스(그리고 확신도, 클래스 아이디)만 벡터에 담습니다.
        if (maxScore > confThresh) {
            float x1 = (cx - w / 2.0f) * scaleX;
            float y1 = (cy - h / 2.0f) * scaleY;
            float boxW = w * scaleX;
            float boxH = h * scaleY;

            cv::Rect box(x1, y1, boxW, boxH); // 탐지된 네모박스입니다.
            cv::Rect bounds(0, 0, origW, origH); // 원본 이미지입니다.

            // 탐지된 네모박스 구했다면서? 근데 왜 원본 이미지와 교집합을 또 구하는데?
            // YOLOv8 모델이 탐지한 네모박스 좌표가 원본 이미지를 벗어났을 수도 있다.
            // 예를 들어, 원본 이미지가 640 640이라고 가정하고, 탐지된 물체는 x1 값이 480이고, boxW가 170이라고 했을 때,
            // xmin은 480, xmax는 650(480 + 170)이 되어버리면 640을 초과하게 된다.
            // 이렇게 되면 오류가 발생할 수 있기 때문에, 원본 이미지와의 교집합을 구함으로써 보정하는 과정이 필요하다.
            box &= bounds; // 원본 이미지와 탐지된 네모박스의 교집합을 구합니다.

            // 탐지된 네모박스, 그 네모박스의 클래스 아이디, 클래스에 대한 확신도를 각각의 벡터에 담습니다.
            boxes.emplace_back(box);
            confidences.emplace_back(maxScore);
            classIds.emplace_back(maxClassId);
        }
    }

    // 탐지된 박스(boxes)와 확신도(confidences)를 담은 벡터, 그리고 확신도 임계값(confThresh), NMS 임계값(nmsThresh)을 통해
    // 총 8400개의 박스 중에 임계값을 넘는 인덱스가 몇번인지 추출합니다.
    // indices에는 만족하는 인덱스 번호가 담깁니다. (예: 54, 74, 5344)
    cv::dnn::NMSBoxes(boxes, confidences, confThresh, nmsThresh, indices);

    // 추출된 인덱스 번호들(indices)만을 가지고 Detection 구조체를 담는 벡터(detections)에 하나씩 밀어넣습니다.
    std::vector<Detection> detections;
    detections.reserve(indices.size());
    for (int idx : indices) {
        // 클래스 생성자에서 reserve로 메모리 공간을 미리 예약해 두었기 때문에, 불필요한 메모리 재할당이 발생하지 않습니다.
        detections.push_back({ boxes[idx], confidences[idx], classIds[idx] });
    }

    // 최종적으로 벡터를 반환합니다.
    return detections;
}

// 실제 추론 함수입니다.
std::vector<Detection> YoloTRT::detect(const cv::Mat& srcImg, float confThresh, float nmsThresh) {
    if (srcImg.empty()) return {};

    // 전처리 과정을 거칩니다.
    preprocess(srcImg);

    // h_input(Host, CPU)에는 이미지의 RGB 정보가 담겨 있고, 그것을 d_input(Device, GPU)로 inputSize만큼 카피합니다.
    cudaMemcpyAsync(d_input, h_input, inputSize, cudaMemcpyHostToDevice, stream);
    // 모델 추론을 진행합니다.
    context->enqueueV3(stream);
    // 추론을 끝낸 출력 텐서.. d_output(Device, GPU)에는 (1, 84, 8400)의 데이터가 메모리 공간에 담겨 있고, 그것을 h_output(Host, CPU)로 outputSize만큼 카피합니다.
    cudaMemcpyAsync(h_output, d_output, outputSize, cudaMemcpyDeviceToHost, stream);
    // 정확한 추론 시간을 측정하기 위해 처리가 끝날 때까지 기다려 줍니다.
    cudaStreamSynchronize(stream);

    // 후처리 과정을 진행합니다.
    return postprocess(srcImg.cols, srcImg.rows, confThresh, nmsThresh);
}

void YoloTRT::inferOnly() {
    context->enqueueV3(stream);
    cudaStreamSynchronize(stream);
}
```

```cpp
#include "YoloTRT.h"
#include <chrono>
#include <numeric>
#include <vector>
#include <iostream>
#include <algorithm>
#include <thread>
#include <atomic>
#include <opencv2/opencv.hpp>

// std::mutex를 하나도 쓰지 않는 고속 lock-free 순환 큐입니다.
class LockFreeFrameQueue {
private:
    // static constexpr을 쓰는 이유는 무엇인가?
    // static은.. 클래스의 각 객체마다 생기는 게 아닌, 해당 클래스의 모든 객체가 공유하는 전역 상수입니다.
    // 인스턴스마다 메모리를 낭비하지 않고 공유하는 용도로 쓰입니다.

    // constexpr은.. 컴파일 시점에 값이 확정되는 완벽한 상수임을 보장합니다.

    // 그래서.. 두 개를 같이 쓰는 이유는..?
    // C++에서 배열의 크기를 선언할 때(cv::Mat ringBuffer[kCapacity])는 컴파일 시점에 반드시 크기를 알 수 있는 상태여야 합니다.
    // static constexpr을 사용하면 메모리 공간을 따로 차지하지 않는 컴파일 타임 상수가 되어서 배열 크기를 지정할 때 사용합니다.
    static constexpr size_t kCapacity = 32; // 링 버퍼의 최대 용량을 32로 정해둡니다.

    // 배열 방식을 쓴 이유, 그리고 std::vector<cv::Mat>과의 차이는 뭐야?
    // 배열 방식은 미리 32개 공간의 고정 크기 배열을 생성합니다.
    // std::vector 방식은 데이터를 추가하거나 크기를 바꿀 때 내부적으로 힙 메모리를 재할당하거나 동적 할당이 일어나서 미세한 딜레이가 생깁니다.
    // 하지만 lock-free 큐 구조에서는 동적 할당이나 메모리 재할당이 일어나면 FPS가 떨어집니다.
    // 따라서 메모리 풀링(Memory Pooling) 기법을 써서 처음 시작할 때 640 640 크기의 방 32개를 미리 파두고,
    // 이후에는 새로 메모리를 할당하지 않고 기존 방에 copyTo()로 픽셀 데이터만 덮어쓰는 방식으로 오버헤드를 줄였습니다.
    cv::Mat ringBuffer[kCapacity]; // 최대 32개의 Mat을 담을 수 있는 링 버퍼를 선언합니다.

    // CPU 하드웨어 레벨에서 연산의 원자성을 보장해 줍니다.
    // 중괄호 표현이 되게 낯설 수 있는데, 쉽게 말해서
    // 객체를 생성하면서 초기값을 0으로 대입하는 C++ 표준 문법입니다.
    std::atomic<size_t> writeIndex{0};
    std::atomic<size_t> readIndex{0};

public:
    LockFreeFrameQueue() {
        // 메모리 풀링: 시작할 때 640 640 크기 방 32개를 미리 파둡니다. (동적 할당 배제)
        for (size_t i = 0; i < kCapacity; i++) {
            ringBuffer[i] = cv::Mat::zeros(640, 640, CV_8UC3);
        }
    }

    // producer: 자물쇠 없이 원자적 연산으로 큐에 삽입합니다.
    // 링 버퍼에 프레임을 밀어넣는 함수입니다.
    bool push(const cv::Mat& frame) {
        // memory_order란?
        // CPU와 컴파일러는 성능을 극대화하기 위해 코드의 실행 순서를 임의로 바꾸는 최적화를 수행합니다.
        // 하지만 멀티스레드 환경에서는 이 순서가 뒤죽박죽되면 데이터가 꼬입니다.
        // 이때 "이 변수를 읽고 쓸 때 스레드 간의 순서를 어떻게 보장할 것인가"를 지정해 주는 것입니다.

        // memory_order_relaxed: 완화된 순서
        // 가장 제한이 없고 빠릅니다. 원자성만 보장될 뿐, 다른 메모리 접근과의 실행 순서를 강제하지는 않습니다.
        // push 함수의 writeIndex에게 이걸 쓰는 이유는, writeIndex는 producer 혼자서 쓰고 관리하는 값이므로
        // 순서 제약 없이 가장 빠르게 현재 값을 읽어오면 되기 때문입니다.

        // memory_order_acquire: 획득
        // 데이터를 읽어들일 때(load) 사용합니다.
        // 이 명령어가 실행된 이후에 나오는 모든 메모리 읽기/쓰기 작업이 이 명령어보다 절대 위로 못올라가게 막아서,
        // 다른 스레드가 쓴 최신 데이터를 안전하게 가져오도록 보장합니다.
        size_t currentWrite = writeIndex.load(std::memory_order_relaxed);
        size_t currentRead = readIndex.load(std::memory_order_acquire);

        // currentWrite: 지금까지 producer가 총 몇개의 프레임을 썼는지 누적 카운트입니다.
        // currentRead: 지금까지 consumer가 총 몇개의 프레임을 읽어갔는지 누적 카운트입니다.
        // currentWrite - currentRead: 현재 큐 안에 남아있는(아직 처리되지 않은) 프레임의 개수입니다.
        // 이 개수가 kCapacity(32)보다 크거나 같다는 뜻은, 링 버퍼가 가득 찼다는 의미이므로, 더이상 push할 수 없습니다.
        if ((currentWrite - currentRead) >= kCapacity) {
            return false; // 자물쇠가 없으므로 스레드를 재우지 않고 즉시 false를 반환합니다.
        }

        // currentWrite 값을 알면, 지금 32개의 방 중에 어떤 방이 비었는지 방 번호(index)를 알 수 있습니다.
        // 35번 프레임을 마지막으로 처리했다면, currentWrite 값은 35가 되고, 이것을 kCapacity(32)로 나눈 나머지는 3이 됩니다.
        // 즉, 3번 방에 35번 프레임이 있었는데, 처리했으므로 다시 써도 되는 방이 되었습니다. 방을 재사용하겠다는 의미입니다.
        // 프레임(frame)을, 미리 파둔 3번 방에 픽셀값만 복사함으로써 복사 오버헤드를 최소화합니다.
        // clone()을 할 필요가 없어진 것이죠.
        size_t index = currentWrite % kCapacity;
        frame.copyTo(ringBuffer[index]);

        // memory_order_release
        // 데이터를 쓸 때(store) 사용합니다.
        // 이 명령어 이전에 수행된 모든 메모리 쓰기 작업이 이 명령어보다 절대 아래로 못내려가게 막습니다.
        writeIndex.store(currentWrite + 1, std::memory_order_release);
        return true;
    }

    // consumer: 자물쇠 없이 원자적 연산으로 큐에서 추출합니다.
    bool pop(cv::Mat& frame, const std::atomic<bool>& stopSignal) {
        while (true) {
            // 여기서는 push 함수와 반대로, currentRead에 memory_order_relaxed를 주고,
            // currentWrite에 memory_order_acquire를 주었습니다.
            // currentRead는 pop에서만 수정하고 관리하기 때문에 순서 제약 없이 가장 빠르게 현재 값을 읽어오면 되기 때문입니다.
            size_t currentRead = readIndex.load(std::memory_order_relaxed);
            size_t currentWrite = writeIndex.load(std::memory_order_acquire);

            // 큐가 비어있는 상태 체크

            // currentRead(pop한 개수)와 currentWrite(push한 개수)가 같다는 건, 큐에 있는걸 모두 다 읽어서 종료되었거나, 아직 시작하지도 않은 상태를 의미합니다.
            if (currentRead == currentWrite) {
                if (stopSignal.load(std::memory_order_relaxed)) {
                    return false; // 동영상 종료 신호(stopSignal)가 true이면, 이제 빠져나옵니다.
                }
                // 아직 할 일이 없기 때문에 Budy Waiting을 방지하고 CPU를 잠시 양보합니다.
                std::this_thread::yield();
                continue;
            }

            // 맨 처음엔 아무것도 읽지 않았으므로 currentRead 값은 0입니다. 그럼 index 값도 0이 됩니다.
            // 링 버퍼에서 0번째 방에 있는 프레임(frame)을 가져옵니다.
            size_t index = currentRead % kCapacity;
            frame = ringBuffer[index];

            // 읽기 완료했음(pop)을 원자적으로 업데이트합니다. 그럼 producer 입장에서 빈자리가 생겼음을 알 수 있습니다.
            readIndex.store(currentRead + 1, std::memory_order_release);
            return true;
        }
    }
};

// 스레드 1: 동영상 전용 디코딩 스레드입니다.
// 비디오 파일의 경로, 큐, 동영상 처리 정지 여부 변수를 매개변수로 받습니다.
void videoDecodingThread(const std::string& videoPath, LockFreeFrameQueue& lfQueue, std::atomic<bool>& stopSignal) {
    cv::VideoCapture cap(videoPath);
    if (!cap.isOpened()) {
        std::cerr << "비디오 파일을 열 수 없습니다: " << videoPath << std::endl;
        stopSignal = true;
        return;
    }

    cv::Mat frame;
    while (!stopSignal) {
        cap >> frame;
        if (frame.empty()) break; // 동영상이 끝났음을 의미합니다.

        // 큐가 가득 차서 push가 실패하면, 자리가 생길 때까지(true가 될 때까지) 무한루프로 대기합니다.
        while (!lfQueue.push(frame) && !stopSignal) {
            std::this_thread::yield();
        }
    }
    cap.release();
    stopSignal = true; // 동영상 처리가 종료되었음을 알려줍니다.
}

int main() {
    // 각 모델을 테스트할 때 여기 엔진 파일명만 바꿔주면서 실행하면 됩니다.
    std::string engineName = "yolov8n.fp32.engine";
    // std::string engineName = "yolov8n.fp16.engine";
    // std::string engineName = "yolov8n.int8.engine";

    YoloTRT detector(engineName);

    // 테스트할 비디오 경로입니다.
    std::string videoPath = "./test_videos/sample.mp4";

    // 비디오 전체 프레임 수를 미리 파악하기 위해 임시 VideoCapture 객체를 생성합니다.
    cv::VideoCapture tempCap(videoPath);
    int totalFrames = static_cast<int>(tempCap.get(cv::CAP_PROP_FRAME_COUNT));
    tempCap.release();

    // warm up 과정이 없으면 max latency가 초반에 팍 튀는 현상이 있기에, warm up을 해주는 게 벤치마킹을 정확하게 측정할 수 있습니다.
    std::cout << "warm up start" << std::endl;
    cv::Mat dummyFrame = cv::Mat::zeros(640, 640, CV_8UC3);
    for (int i = 0; i < 50; i++) {
        detector.detect(dummyFrame, 0.25f, 0.45f);
    }
    std::cout << "warm up end" << std::endl;

    LockFreeFrameQueue lfQueue;
    std::atomic<bool> stopSignal(false);
    std::vector<double> latencies;
    // 전체 프레임 수 만큼 메모리 공간을 미리 할당합니다.
    latencies.reserve(totalFrames);

    // 동영상 처리 스레드를 가동합니다. CPU가 동영상을 무정지로 계속 읽어서 큐에 최대 32개까지 쌓습니다.
    std::thread reader(videoDecodingThread, videoPath, std::ref(lfQueue), std::ref(stopSignal));

    int frameCount = 0;
    while (true) {
        cv::Mat frame;
        // 동영상 처리 스레드가 읽어서 push된 프레임을 비동기적으로 꺼냅니다(pop). 없으면 대기합니다.
        if (!lfQueue.pop(frame, stopSignal)) {
            break;
        }

        auto start = std::chrono::high_resolution_clock::now();

        // 실제 추론 코드입니다.
        auto detections = detector.detect(frame, 0.25f, 0.45f);
        // 탐지된 박스들(detections)을 프레임 위에 그려줍니다.
        for (const auto& det : detections) {
            cv::rectangle(frame, det.box, cv::Scalar(0, 255, 0), 2);
        }

        auto end = std::chrono::high_resolution_clock::now();
        double ms = std::chrono::duration<double, std::milli>(end - start).count();
        latencies.push_back(ms);
        frameCount++;
    }
    // 쓰레드 안전 종료 및 합류
    // join(): 
    // 메인 스레드가 자기 일을 다 마쳤는데, 자기가 먼저 프로그램을 종료해버리면 다른 스레드(reader)는 메모리 주소가 날라가서 에러가 납니다.
    // 그래서 reader.join()을 호출하면, 메인 스레드가 합류 지점에 멈춰서서, "일꾼 스레드가 일을 다 끝내고 안전하게 합류해서 돌아올 때까지 여기서 기다릴게"라는 명령어입니다.
    // joinable():
    // 스레드가 합류할 수 있는 상태인가(true)를 체크하고, 맞다면 join()하기 위한 안전장치입니다.
    if (reader.joinable()) {
        reader.join();
    }

    double sum = std::accumulate(latencies.begin(), latencies.end(), 0.0);
    double avg = sum / latencies.size();
    // min과 max를 구하는 방식이 조금 독특합니다. 별(*)을 붙이는 이유
    // std::min_element가 최솟값 숫자 자체를 반환하는 게 아니라, 최솟값이 위치한 주소값을 반환하기 위함입니다.
    // 별(*)을 붙여 역참조를 해서 주소에 있는 알맹이 값을 가져옵니다.
    double min = *std::min_element(latencies.begin(), latencies.end());
    double max = *std::max_element(latencies.begin(), latencies.end());

    std::cout << "================ [lock-free 큐 고속 비동기 TRT Video 벤치마크] ================" << std::endl;
    std::cout << "사용한 가속 엔진: " << engineName << std::endl;
    std::cout << "처리 프레임 수: " << frameCount << " / " << totalFrames << std::endl;
    std::cout << "순수 추론 파이프라인 Latency (Avg): " << cv::format("%.2f", avg) << " ms" << std::endl;
    std::cout << "최소 Latency (Min): " << cv::format("%.2f", min) << " ms" << std::endl;
    std::cout << "최대 Latency (Max): " << cv::format("%.2f", max) << " ms" << std::endl;
    std::cout << "최종 lock-free 파이프라인 처리 속도: " << cv::format("%.1f", 1000.0 / avg) << " FPS" << std::endl;
    std::cout << "=========================================================================" << std::endl;

    return 0;
}
```
